# Working in this repository

- Use `uv run` to execute commands. Use `uv pip install`, never `pip install`, when installation is necessary.
- Read [docs/DEVELOPMENT_NOTES.md](docs/DEVELOPMENT_NOTES.md) before changing course structure, physics, rendering, or Streamlit lifecycle behavior.
- Keep mathematical calculations in `src/physics/` and Streamlit presentation in `src/ui/`. Make units, sign conventions, assumptions and model limits visible beside calculators.
- Render display equations with the helpers in `src/ui/pedagogy.py`; do not put multiline display math in `st.markdown`, alerts, or raw HTML.
- Prose blocks containing a blank line must go through `render_prose_and_latex`, which dedents them. A triple-quoted literal passed straight to `st.markdown` keeps its source indentation, and four or more leading spaces after a blank line makes markdown treat it as a code block, so the markup and the maths both render literally.
- Mark angles only where they are true: a plan or true-shape view, never an axonometric projection, which foreshortens each direction differently. Draw both bounding rays from the vertex.
- Unicode has no subscript for `w` or for capitals; use `svg_diagrams._sub()` rather than guessing a numeric entity, which lands in the currency block.
- Compute worked-example numbers from the app's own defaults, and prefer having the app recompute a claimed constant over asserting it. This is not only about worked examples: a panel that says a coefficient was integrated must integrate it. Blasius `delta*`/`theta` and the pipe `alpha`/`beta` were hard-coded (and `alpha_turb` was wrong by half the correction) while the lesson claimed otherwise.
- No equation is presented as a quotable formula. Use `render_derivation` from `src/ui/pedagogy.py`, whose steps are `(heading, body)` pairs: the heading names the balance or geometric fact being invoked, and the body says **why** that step is allowed before showing any algebra. Check every numeric claim against a computation rather than against memory, and cross-reference the chapter that established each prerequisite.
- Use `src/ui/state.py`'s `persistent_input` with unique explicit keys for lesson controls and self-checks, and `persistent_editor` for editable tables. Keys alone do not survive chapter changes; never persist button events. Test leaving and returning to a chapter, not just editing within it.
- Test geometry against physical invariants (rigid rotation preserves lengths, incompressible deformation preserves area). Keep instantaneous strain/spin decomposition distinct from finite-time motion; state which variables are held fixed in scaling comparisons.
- Use the existing native-image SVG renderer and `render_plot` wrapper. Check actual browser rendering as well as Python tests for visual or interaction changes.
- When adding a chapter/module, update the lesson metadata, app tabs/imports, source fingerprint/reload list, cross-references and README together.
- `src/ui/learning_path.py` is the only place the course names or numbers itself: `PARTS`, `NAV_LABELS` and `LESSONS` feed the banner route, the chapter navigation, the chapter eyebrow and the sidebar map. Do not hand-write a second list of chapters anywhere. Three had accumulated, disagreeing: the banner numbered the twelve chapters 01–06, the navigation numbered them 1–12, and the sidebar map used a third set of titles.
- Never call `st.rerun()` from the sidebar (or anywhere before the chapter radio). It aborts the run before that widget is instantiated, so Streamlit garbage-collects `chapter_nav` and the reader is silently returned to chapter 1. Set the state and let the current pass use it; the sidebar already runs first.
- Preserve `fileWatcherType = "none"` and `fastReruns = false` unless a real-browser regression demonstrates that an alternative works. A fully drawn page and a passing AppTest do not establish that live widgets work.
- Run relevant tests after changes. For lifecycle/network UI changes, also run `tests/browser_smoke.py` against the running app; details and limitations are in the development notes.
- For teaching-figure changes, run `tests/browser_education.py` and inspect its screenshots, including narrow-screen scrolling. On same-chapter reruns, wait for changed output before checking completion; the existing recap alone is not evidence of a new render.

These instructions describe the current project workflow, not permission to publish, deploy or discard existing changes.
